# Machine learning — module plan

A new standalone module, `machine-learning/`. It is the first of three foundation modules
(Machine learning, then Tensors, then CNNs). It sits under the Generative AI family: a
language model is the same learning loop run at very large scale, so this module is where a
reader learns the loop.

> **Status:** built and registered; fact-check in progress. Plan written 2026-10. See the status table at the end.

## Decisions

| Decision | Choice |
| --- | --- |
| Audience | Product leaders **and** enterprise technology leaders. Two layers in every lesson: a leader briefing in the body, and one runnable example under the hood for engineers. |
| Promise | After this module a reader can say whether a problem needs ML, ask for the right data, read a training curve and a metrics table, and spot the five ways an ML feature fails in production. |
| Shape | 8 lessons and a recap. Each lesson has a worked example, an Under the hood section with code that runs, a diagram, a checklist and Sources. |
| Code | Pure Python standard library, so it runs anywhere with no install. Each file ends with `assert` lines. `machine-learning/code/test_examples.py` runs them all. |
| Running example | One invented product: a subscription service that wants to predict which customers will cancel. Every lesson reuses it, so the reader meets one dataset and learns its failure modes in turn. All data is generated by code with a fixed seed and labelled as invented. |
| Out of scope | Deep-learning internals (Tensors and CNNs modules), transformers and LLM training (`llms`), prompting, RAG, fine-tuning. This module links to them and does not repeat them. |

## The overlap gate

Per `CONTENT_FRAMEWORK.md` section 7. What the neighbours already cover, and the delta this
module adds.

| Neighbour | What it already covers | Delta in this module |
| --- | --- | --- |
| `llms/what-is-an-llm` | Training happens once, inference runs every time. | The training loop itself: loss, gradient step, learning rate. A runnable one. |
| `llms/prompting-vs-rag-vs-finetuning`, `generative-ai/build-buy-or-fine-tune` | When to prompt, retrieve or fine-tune an LLM. | The step before: whether the problem needs a learned model at all (rules vs ML vs LLM). |
| `evaluation-and-observability` | Eval sets and observability for LLM features. | The classic metrics and their traps (accuracy on imbalanced data, thresholds, calibration), and drift in a learned model. |
| `rag-vector-databases/retrieval-quality` | Precision and recall for retrieval. | Precision and recall for any classifier, and how to pick the threshold from the cost of each error. |
| `technical-product-management/metrics-and-experimentation` | Product metrics and A/B tests. | Offline model metrics versus online product metrics, and why they disagree. |
| `first-principles` | Reasoning from fundamentals. | None. Not an overlap. |
| `content/01-inference-internals` | Serving cost of large models. | None. This module stops at training and lifecycle. |

Every lesson links to the neighbour that goes deeper, and says what it will not repeat.

## The lessons

| # | Lesson | The question it answers | What is new (the delta) | Worked example (invented) | Runnable file |
| --- | --- | --- | --- | --- | --- |
| 1 | What machine learning is, and when to use it | Do we need ML, or are rules enough, or is this an LLM job? | A three-way decision table: rules, ML, LLM. A "start without ML" baseline rule. | 2 | Data: features, labels, splits and leakage | Is our data good enough, and is the test honest? | A data-readiness checklist. Leakage with a worked failure. Random versus time-based splits. | A leaky feature gives 97% in testing and collapses in "production" | `lesson2_leakage.py` |

| 4 | Generalization: overfitting and the bias–variance tradeoff | Why does it work in testing and fail on real data? | Learning curves as a decision tool: more data, simpler model, or better features. Recap: real examples, a table of one idea and one question per lesson, a through-line, and

## What each lesson contains

Per `CONTENT_FRAMEWORK.md` section 2: title, review stamp, TL;DR, a 🎯 briefing, a mental
model diagram, mechanics, a labelled worked example, tradeoffs, failure modes, Under the
hood, checklist, related lessons, Sources. Readability targets: average sentence 20 words or
fewer, no more than 12% of sentences over 30 words, Flesch 50 or higher. Style follows
`WRITING-STYLE.md`.

## Sources to use

Primary sources only, each with an "as of" date: the scikit-learn user guide (common
pitfalls, cross-validation, metrics, calibration); Zinkevich, *Rules of Machine Learning*
(Google); Sculley et al., *Hidden Technical Debt in Machine Learning Systems* (NeurIPS 2015);
Mitchell, *Machine Learning* (1997); Goodfellow, Bengio and Courville, *Deep Learning* (2016);
Rumelhart, Hinton and Williams (1986); Belkin et al. (PNAS 2019) for the limits of the
classic bias–variance picture; Grinsztajn et al. (NeurIPS 2022) for trees on tabular data;
Guo et al. (ICML 2017) for calibration; Gama et al. (ACM Computing Surveys 2014) for concept
drift; Kaufman, Rosset and Perlich (2012) for leakage. No unsourced statistics. Numbers in
worked examples come from the code and are labelled invented.

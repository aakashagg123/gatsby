Memory & context

Five lessons · promise → scope → write → read → risk

Memory isn't free infrastructure — every step of it is a decision someone should make on purpose.

Lesson 1 · The promise
Memory is a feature you choose to build
Ship the goldfish, or ship the oversharer — both are the predictable result of nobody deciding.
Lesson 2 · The scope
Three scopes · session · user · organizational
Session

A sticky note · one conversation only

User

A personal file · one person, many visits

Organizational

A shared handbook · team-wide with an owner

Lesson 3 · The write path
What is saved, when, and how it changes
Worth saving? New or a conflict? When does it expire? Decide before the first write.
Lesson 4 · Where it comes from
Three designs · load · retrieve · agent notes
Small and stable: load it. Large: search it. Long task: let the agent keep notes.
Lesson 5 · When it breaks
Four failure modes to test for by default
Stale

Product acts confidently on outdated info

Leaked

Crosses tenant, user, or org boundary

Stuck

User can't see, correct, or delete it

Poisoned

Planted instruction acts in later sessions
